# Repository contract

Maintain Osiris's private library of reusable operations, creative, product, and tool skills. The owner expanded the original social-only scope on 29 October 2026.

- Follow the skill-creator workflow when creating or substantially revising a skill.
- Put skills in `skills/<category>/<skill-name>/`; the folder and frontmatter name must match. Preserve existing paths when adding new categories.
- Keep entrypoints focused. Use supporting references only for material that changes execution decisions.
- Preserve the user's task-specific authorization. A skill is not permission to access another account, publish, change delivery, or perform unrelated writes.
- Store reusable instructions, necessary non-secret environment pointers, and sanitized examples here. Keep client/account mappings, customer details, approvals, private record URLs, exports, screenshots, credentials and browser state in the authorized task workspace. Public documentation and product entrypoint URLs are allowed.
- Keep this repository private. Do not add a public license or broaden sharing without the owner's request.
- Validate changed skills and execute meaningful checks for changed helpers. Distinguish offline validation from live browser acceptance.
- Collect custom skills and deliberately adapted workflows. Keep upstream attribution and bundled licenses. Inventory system/plugin/vendor skill collections separately rather than copying caches into this library.
- Before replacing a same-name skill, compare content and provenance. Preserve unresolved variants separately and report them; modification time alone does not establish the authoritative version.
- Update the catalog and source inventory with additions, transformations, exclusions, validation, and unresolved VPS skills. Never execute a collected skill merely to archive it.
