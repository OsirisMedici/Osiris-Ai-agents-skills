# FTI task template

Version: 1
Approved: 26 October 2026

Read this file before every FTI draft. It is the shared format for new tasks and requested description rewrites. Use the same structure across task topics; change the task content to fit the actual request.

## Title and description

Use an action-led title with the destination board's code. On Needs my attention, use `ATT-NNN · Task title`.

Write one opening paragraph of 3 to 4 short sentences. Explain the work, why it matters, and the starting point. Follow it with 2 to 4 action bullets, then one paragraph starting with `Outcome:` and naming one observable result. Add a short P.S. only when a necessary caveat or reference does not fit elsewhere.

The finished description should fit comfortably on one screen. Aim for about 100 to 180 words when the task allows it. Use plain, warm, direct language that a teammate and an AI agent can both follow. Keep longer evidence in linked documentation. For broad work, capture the first useful scope and include unresolved decisions as actions rather than inventing answers.

```text
[BOARD-NNN] · [Action-led task title]

[What needs to happen.] [Why it matters or who it helps.] [Relevant starting point or scope.]

- [First useful action.]
- [Next action.]
- [Another action, if needed.]
- [Another action, if needed.]

Outcome: [One observable result that makes review or completion clear.]

P.S. [Only if useful.]
```

Replace every placeholder and omit unused optional lines. The brackets illustrate fields; they are not part of the saved title or body. Save real paragraph and bullet-list blocks in Feedback, rather than one text field containing Markdown markers.

## Acceptance check

Before saving and again after reopening the saved task, check that:

- The title starts with the correct board code and an action.
- The opening is one short paragraph with 3 to 4 sentences, followed by 2 to 4 native action bullets and one observable outcome paragraph.
- Any P.S. adds information the reader needs. The description contains no unused placeholders, invented dates or responsibilities, or technical logs.
- The saved content matches the draft, and the description is readable in the task editor's first viewport.

## Example

Illustrative title: `ATT-001 · Create role-specific team SOPs and daily reporting expectations`. Preserve this structure and level of detail when drafting other tasks. Resolve real task references in the authorized workspace.

Create a short SOP for each team member based on their actual role. Each person should know where to log in, find tasks, and post updates. Define what they must communicate beyond completing assigned work.

- Map each person's responsibilities and the tools and access their role needs.
- Explain the daily workflow: find tasks in Feedback, update progress, share files, and request review.
- Set a simple end-of-day update covering completed work, pending work, blockers, and the next day's plan.
- Agree what needs an early heads-up, such as delays, absence, access issues, or help and decisions needed, and where to report it.

Outcome: Each team member has an approved, role-specific SOP and can follow the work and reporting process without repeated reminders.
