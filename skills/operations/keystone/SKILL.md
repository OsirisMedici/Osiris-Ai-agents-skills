# Keystone project sync

Keep a project's plan, owned tasks and call history coherent. Resolve the project
folder and participant roles from the user's brief. The original convention is
`Keystone/` with a plan, tasks, optional partner notes and `Transcripts/` folder;
equivalent existing project records work too. No client or participant is built in.

## Process a transcript

Read the current plan and tasks before processing the supplied transcript.
Extract decisions, task changes, owners, stated deadlines and blockers. Save a
dated transcript note with call participants, duration and recording link only
when supplied, followed by key moments, decisions, tasks and the full transcript
when the user is authorized to retain it.

Update the existing task records without losing completed history. Change the
plan only for real scope, phase or structural decisions. Keep uncertain owners
or dates explicit. Record collaborator development observations only when the
user asks for that private record, using observed behavior rather than inferred
personality or psychological claims.

Return what advanced, what the next call needs to accomplish, and unresolved
decisions. Keep private transcripts and record links in the authorized workspace.

## Status check or pre-call brief

Read the plan, task board and latest relevant call notes. Explain current phase,
in-progress and blocked tasks, what each participant owes, the last decisions and
the questions the next call can resolve. Separate recorded commitments from
unverified completion. This skill saves records; it does not contact participants.
