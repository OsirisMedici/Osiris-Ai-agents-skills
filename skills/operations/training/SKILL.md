# Training log

Track a training partner, the SOP being developed and concrete learning outcomes
in the user's existing private workspace. Locate `_TRAINING.md` or its equivalent.
This package contains no staff roster, past sessions or personal commitments.

## Plan today

Use the supplied partner and topic; ask for whichever is missing. Update today's
date, partner and topic. If the session belongs to an ongoing SOP, preserve or
record its name, start date, owner and current status. Planning does not prove
that training happened.

## Record a completed session

Append the actual date, partner, topic and observable output. Prefer what the
learner can now do or what was built over a vague "talked about" description.
Keep the latest five rows visible if using the original rolling format, and
archive older rows so the record is preserved. Clear today's plan only when the
completed session matches it. Update SOP status from the user's report.

## Update an SOP

Change only the named SOP's recorded status. When it is shipped, ask about the
next one only if needed. Do not invent a successor or claim the SOP was tested.

Read back the saved fields. Refresh an already-configured cockpit using its
read-only mode when available. Reminder thresholds must come from the user's
current preferences; empty fields do not establish that a commitment was missed.
Return the saved path and the specific change. Do not message the learner.
