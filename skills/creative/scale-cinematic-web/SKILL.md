# Cinematic web design

Adapted from the MIT instruction/reference portion of MotionSites Web Builder. `LICENSE` retains the complete upstream terms. The restricted example-prompt and media collection is not bundled. Use original, user-provided or individually permitted references and assets.

## Define the section

Inspect the existing product, page, brand and assets. Identify the audience, main action, relevant content and one visual idea that supports them. Use the requested scope; a hero does not imply rebuilding the rest of a website. Reuse known answers and ask only when a decision changes the result.

Study a few relevant original references and record the particular composition or behavior they inform. Read `references/spec-template.md` for a detailed specification, `references/craft.md` for critique and the relevant technique reference only when the chosen idea needs it.

## Choose the material

Prefer the user's assets, then permitted generated or licensed assets when the task needs them. Record attribution and actual rights. If useful material is unavailable, a deliberate typography-led treatment is a valid outcome. Keep references to upstream galleries as links; the package's MIT grant does not cover the excluded prompt/media collection.

Write concrete type, color, layout, breakpoints and interaction decisions. Tie motion to the visual story and include a static/reduced-motion presentation. An element that contributes no information or useful emphasis can stay still.

## Build and review

Build in the owning project's existing stack and use Bun for JS/TS work. A simple standalone page may be buildless; a component task does not justify a new framework. Inspect current dependencies and library documentation before using a retained recipe, because recipe versions are dated examples.

Use the supported in-app Browser for inspection, screenshots and playback. The upstream screenshot helper is excluded from the active workflow; use `references/review.md` as a critique rubric and revise observed weaknesses. Capture the actual result at the relevant desktop and phone sizes and check focus, touch, legibility and reduced motion. A code-only review must report rendered checks as unverified.

Deliver the requested files or builder prompt, the design reasoning, actual validation and any asset that still needs replacement. Follow the current project's publishing and completion rules. This adaptation adds no advertising, referral tracking, paid-service requirement or default subscription workflow.
