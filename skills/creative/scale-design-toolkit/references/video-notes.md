# Design practices from liked videos

Reviewed 11 November 2026 for a reusable toolkit across Scale's projects. These eight videos are members of the authenticated account's Liked videos inventory. Exact titles, creators, durations, descriptions and chapter markers came from YouTube's first-party metadata. One auto-generated transcript was reviewed in full. The remaining seven entries use creator descriptions and chapter markers, with that limit recorded per entry below. The child browser could not access the parent in-app browser session; the parent supplied the successful transcript export.

This review extracts design practices. Creator claims about higher perceived value or conversion are not measured outcomes for Scale. Referenced galleries and asset libraries are places to research; their inclusion does not license every listed asset.

## Reusable order of work

1. Write the audience, task and desired result before choosing the visual treatment.
2. Collect references for specific decisions and analyze their structure rather than copying a complete screen.
3. Define a coherent visual identity before combining sections or components.
4. Build the page around a clear value proposition, evidence and an appropriate next action.
5. Use motion when it explains or responds to an interaction. Check the real implementation and reduced-motion behavior separately.
6. Keep a source and license record for fonts, illustrations, mockups and code.

This sequence is a proposed toolkit workflow assembled from the sources below, not a claim that every creator teaches every step.

### Interface critique

**[5 SaaS UI/UX mistakes that SCREAM you Vibe Code](https://www.youtube.com/watch?v=PDcQJOPby1k), Kole Jain, 6:32.**

The description offers a short SaaS interface critique and links the creator's [Figma resource page](https://www.kolejain.com/resources?scrollTo=vibe-coded-saas). The full auto-generated transcript was reviewed. The useful observed changes are:

- At [00:24](https://www.youtube.com/watch?v=PDcQJOPby1k&t=24), replace decorative emoji with a coherent interface icon family when appropriate. Phosphor and Lucide are examples named by the creator.
- At [00:39](https://www.youtube.com/watch?v=PDcQJOPby1k&t=39), make deliberate palette choices and place color in useful data rather than arbitrary decoration.
- At [01:11](https://www.youtube.com/watch?v=PDcQJOPby1k&t=71), remove repeated KPI groups from unrelated screens and organize navigation around each screen's task.
- At [02:04](https://www.youtube.com/watch?v=PDcQJOPby1k&t=124), choose a suitable modal or panel and collapse advanced settings until needed.
- At [03:24](https://www.youtube.com/watch?v=PDcQJOPby1k&t=204), remove nonfunctional cards and give pricing, discounts and plan differences a clear hierarchy.
- At [05:36](https://www.youtube.com/watch?v=PDcQJOPby1k&t=336), explain the product with relevant interface visuals.

These are context-dependent redesign decisions, not a requirement to add charts or hide actions in every product. The Builder.io segment is sponsorship, and the conversion claims were not independently tested.

Review level: full auto-generated transcript, creator description and linked resource URL. The Figma resource page could not be read through the web tool in this review, so download availability and file licenses remain unverified. Transcript capture: saved transcript (private source capture retained in ScaleHQ).

### Brand color

**[Why Some Brands Look Expensive (Before You Know What They Sell)](https://www.youtube.com/watch?v=BgzB73FUOpU), Peter Reitano, 2:23.**

The description uses color, restraint and a 60/30/10 allocation as branding heuristics. Keep the useful task concrete: choose which color supports the main surface, secondary surfaces and accents, then test the result in the actual design. A ratio or a hue does not establish a universal price perception or a conversion improvement.

## Small first trial

For one real upcoming page, fill a one-page brief, record three specific references, choose the type and color roles, outline the content, and build one representative section. Compare that section with its intended audience and reference decisions before building the rest. Keep the actual source links, screenshots, asset licenses and acceptance results with the project so later work can reuse what passed.
