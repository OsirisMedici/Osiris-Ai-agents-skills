## Install and use

You need Git and Python 3.9 or later for the sync helper. Run:

```sh
git clone https://github.com/OsirisMedici/Osiris-Ai-agents-skills.git
cd Osiris-Ai-agents-skills
python3 skills/tools/osiris-skills-sync/scripts/sync.py --apply
```

The default destination is `~/.codex/skills`, or `$CODEX_HOME/skills` when configured. On Windows, use `py -3` if that is your Python command. Use `--skills-dir /path/to/skills` for another agent's supported skill directory. Reopen your agent session after installation.

To install one skill, click its **Open skill** link above, inspect the instructions and requirements, then copy its entire folder into your agent's skill directory. Keep its supporting files together. Review an existing same-name installation before replacing it. The **Download all skills** link provides the repository ZIP without requiring Git.

Invoke a skill by its frontmatter name, for example:

```text
$full-flow Build the feature described in this issue.
$crayon-scale Design the product flow we discussed.
$title /path/to/article.md
```

Claude Code users can use the corresponding slash command, such as `/title`, after installing the folder in their supported skills directory.

For later updates, run the sync helper again or invoke [`$osiris-skills-sync`](skills/tools/osiris-skills-sync/SKILL.md). Run the helper without `--apply` to preview changes. It backs up tracked packages before updating them and preserves differing local copies for review. Pulling requires no GitHub account.

## Requirements and private configuration

Some skills need a particular application, operating system, connected service or tool. Read the skill before installing its dependencies. An editor skill needs its editor; a calendar, task or advertising skill needs an authorized connection to that service.

Workspace paths in the public packages describe layouts to resolve in your own setup. Private client files, account mappings, calendar IDs, personal profiles, browser sessions and credentials are not included. Installing a skill does not execute it or grant permission to contact people, publish content or change an external service.

The custom vault research workflow is published as `vault-research` so it can coexist with a separate engineering skill named `research`. The legacy index workflow uses its original frontmatter command, `blueprint-index`.

## Maintenance

Follow [AGENTS.md](AGENTS.md). Keep each package in `skills/<category>/<skill-name>/`, preserve attribution and existing licenses, and leave system/plugin/vendor collections outside this custom library. No new license is implied by public visibility.

When adding a skill, add a one-sentence description to [the catalog source](docs/skill-catalog.json), then run:

```sh
python3 scripts/build_catalog.py
python3 scripts/build_catalog.py --check
```

The catalog check rejects missing descriptions, stale entries and mismatched package names. Validate changed skill packages with the available Skill Creator validator, run meaningful checks for changed helpers, and regenerate the sync inventory. Keep private execution records in their authorized workspace.
